# Cybersecurity Simulation Scenario

## 1. Organization

Name: Asterix Financial Services

Asterix Financial Services is a fictional financial services company. Employees use corporate devices and internal applications to perform daily business activities.

The organization handles sensitive financial reports and customer records.

## 2. Organization Size

- Employees: 15
- Corporate devices: 18
- Applications: 3
- Simulation duration: 36 hours
- Target dataset size: 750 events

## 3. Applications

1. Identity Provider: Handles employee authentication.
2. Document Portal: Stores and manages company documents.
3. Internal Web Application: Supports everyday business operations.

## 4. Security Incident

An external attacker compromises an employee's credentials.

Using the compromised account, the attacker authenticates to the company's systems, accesses sensitive documents, and exfiltrates company data.

The incident must appear within normal employee activity rather than as an isolated sequence of malicious events.

## 5. Simulation Objective

Generate an OCSF 1.9-aligned dataset containing realistic normal business activity and a connected, multi-step cybersecurity incident.

The dataset must preserve consistent relationships between users, devices, applications, sessions, and events.

## 6. Incident Timeline

### Incident ID

INC-001

### Compromised Employee

- User ID: USR-007
- Role: Finance Analyst
- Legitimate device: DEV-007

### Attacker

- Attacker device: ATK-001
- Device type: Unmanaged external laptop
- Compromised account: USR-007

### Attack Sequence

1. 09:00 - Normal Login
   The employee logs into the corporate identity provider
   using their legitimate device, DEV-007.

2. 10:15 - Attacker Authentication
   The attacker successfully logs into the employee's
   account using the external device, ATK-001.

3. 10:18 - Unauthorized Application Access
   The attacker accesses the company document portal
   using the compromised account.

4. 10:22 - Sensitive Document Download
   The attacker downloads confidential financial reports
   from the document portal.

5. 10:30 - Data Exfiltration
   The attacker transfers the downloaded documents to
   an external destination.

### Assumptions

- The attacker obtained the employee's credentials before
  the simulated incident begins.
- The credential theft itself is outside the simulation scope.
- The attacker device is not a corporate-managed device.
- All attacker actions use the compromised employee account.
- Incident events share the identifier INC-001 in ground truth.
- Normal business activity continues during the incident.

## 7. Entity Relationships

### Employee and Device

- USR-007 is a legitimate employee.
- USR-007 is assigned corporate device DEV-007.
- DEV-007 belongs to Asterix Financial Services.
- USR-007 has authorized access to the Document Portal.

### Attacker and Device

- ATK-001 is an external, unmanaged device.
- ATK-001 is not owned by the organization.
- The attacker uses the compromised account USR-007.
- ATK-001 must be represented in the entity registry.

### Authentication Sessions

- SES-001: Legitimate session for USR-007 on DEV-007.
- SES-002: Attacker session for USR-007 on ATK-001.
- Each session has its own unique identifier.
- Both sessions reference the same user account.

### Incident Relationships

- Incident ID: INC-001
- Compromised account: USR-007
- Attacker device: ATK-001
- Attacker session: SES-002

All attacker actions after authentication must reference
SES-002 when the event type supports session information.

The incident's ground truth must reference the actual
event IDs generated by the simulator.
